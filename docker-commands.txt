Releasing (on a dev machine, from a clean, up-to-date master):
./release.sh
  Tags master as vYYYY.MM.DD (or .2, .3 ... for a second release the same day)
  and publishes a GitHub Release with notes generated from the merged PRs.

Deploying on the web server (keeps .env and .env.db intact):
./deploy.sh              newest release tag
./deploy.sh v2026.11.07  that tag; this is also how you roll back

What is running right now:
git describe --tags

Manual Docker Compose v2 commands (note the space: "docker compose", not "docker-compose"):

Build and start the stack in the background:
docker compose up -d --build

-d runs the containers in the background so that you can continue to use the terminal.
--build rebuilds the images with whatever changes you have made since the last build.

Stop the stack:
docker compose down

Follow the web container's log (gunicorn tracebacks land here):
docker compose logs -f web
